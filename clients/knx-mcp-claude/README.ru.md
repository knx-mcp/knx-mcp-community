# KNX-MCP для Claude Desktop

[English](README.md) · [Deutsch](README.de.md) · [Français](README.fr.md) · [Čeština](README.cs.md) · [Italiano](README.it.md) · [Русский](README.ru.md)

Подключите Claude Desktop к одному или нескольким экземплярам ETS5/ETS6 в Windows,
задав каждому понятное имя. Каждый инструмент указывает своё целевое подключение.
Это позволяет работать с несколькими объектами, не смешивая их сеансы, данные
доступа и настройки доверия сертификатам.

| Кратко | Подробности |
| --- | --- |
| Клиент | **1.0.4** |
| Установочный пакет | `KNX-MCP-1.0.4.mcpb` |
| Базовая совместимая версия приложения ETS | KNX-MCP **1.2.0.4** и совместимые последующие версии |
| Платформа | Claude Desktop в Windows |
| Среда выполнения | Node.js **22.16.0 или новее**, предоставляемая хостом |
| Издатель | Gerald Docenko |
| Поддержка | [support@knx-mcp.com](mailto:support@knx-mcp.com) |

У клиента и приложения ETS независимые номера версий. Клиенту не требуются
сторонние пакеты JavaScript или загрузка пакетов при запуске.

## Требования

Перед установкой подготовьте:

- Лицензированную установку **ETS5 или ETS6**.
- **Приложение KNX-MCP для ETS**, отдельно установленное через MyKNX.
- **Claude Desktop в Windows** с поддержкой расширений MCPB.
- Сетевой доступ с компьютера Claude к каждой нужной конечной точке ETS.

Файл `.mcpb` устанавливает расширение Claude. Приложение ETS установите отдельно
на компьютер, где работает ETS. В других хостах или режимах выполнения поведение
может отличаться.

## Установка с экспортированными профилями

### 1. Подготовьте ETS и экспортируйте профиль

1. Откройте нужный проект в ETS и запустите его конечную точку MCP в панели KNX-MCP.
2. В настройках сервера, в разделе **HTTPS**, включите HTTPS, выберите или создайте
   сертификат, соответствующий адресу конечной точки, и примените настройки.
3. В разделе **Claude One-Click-Installation KNX-MCP** задайте понятное имя
   подключения и сохраните `KNX-MCP-<name>.json` в постоянной закрытой папке.

Повторите эти действия для каждой дополнительной конечной точки ETS, которую
хотите использовать.

### 2. Установите расширение в Claude

1. Установите **`KNX-MCP-1.0.4.mcpb`** в настройках расширений Claude.
2. В поле **Профили подключения (рекомендуется)** выберите экспортированные
   профили и сохраните настройки. Можно выбрать до **32 профилей**.
3. Полностью завершите Claude, включая процесс в области уведомлений,
   и запустите его снова.
4. Откройте **новый чат** с включённым KNX-MCP.

В [руководстве по распространению](release/README.md) описаны файлы пакета
и их контрольные суммы.

### 3. Проверьте подключение

1. Попросите Claude вызвать **`knx_connections`**.
2. Для каждого нужного подключения попросите выполнить **`ets_list_projects`**.
3. Перед изменениями проверьте сведения о сервере и проекте. Начните с режима
   **Только чтение** в ETS.

### Храните профили конфиденциально и по постоянным путям

Профили используют формат `knx-mcp-claude/v1`:

- Профиль содержит **ключ доступа в открытом виде** и открытый сертификат
  сервера. Закрытый ключ сертификата в профиль никогда не входит.
- Доверие сертификату действует только для этого подключения. Запись доверия
  на уровне всей системы не создаётся.
- Оставляйте выбранные файлы по сохранённым путям. После перемещения или
  переименования обновите выбор в Claude и полностью перезапустите приложение.

**Никогда не загружайте профили в чаты, обращения поддержки или публичные
репозитории.**

## Несколько подключений и имена инструментов

Задайте каждому подключению отдельное имя, например `Office-ETS5` или
`Office-ETS6`. Инструмент конкретного подключения может называться
`Office-ETS6__ets_list_projects`; его отображаемый заголовок содержит полное имя
подключения.

- Неподдерживаемые символы нормализуются в технических именах инструментов.
- К совпадающим или длинным именам может добавляться различающий суффикс.
- Отключённые подключения сохраняют своё пространство имён. Вызов никогда не
  перенаправляется на другой объект из-за недоступности нужного объекта.

Отображаемое имя — это метка, а не подтверждение версии удалённой ETS.
Перед изменениями проверьте сведения о сервере и текущий проект.

## Два необязательных ручных подключения

Можно использовать экспортированные профили, ручные подключения или оба варианта.
У каждого ручного подключения три поля:

| Поле | Что ввести |
| --- | --- |
| **Имя** | Понятное и уникальное имя подключения |
| **Remote / Local URL** | Полный адрес, например `https://ets-pc.example:51900/mcp` |
| **Bearer token** | Только ключ доступа, без слова `Bearer` |

**Заполните все три поля блока либо оставьте их все пустыми.**
Не задавайте одну конечную точку дважды: неоднозначные записи отключаются.

Если в URL не указан путь, добавляется `/mcp`. `localhost` означает компьютер,
на котором работает Claude; ETS может работать на другом компьютере.

### HTTPS

Сертификат должен соответствовать имени узла или IP-адресу в URL и приниматься
поддерживаемыми источниками доверия Node/Windows для учётной записи,
под которой работает Claude.

Импортируйте только проверенный открытый сертификат либо используйте
экспортированный профиль. Расширение не меняет хранилища сертификатов.

### HTTP для осознанного тестирования

Явно включите **Разрешить незашифрованный HTTP для тестовых подключений**,
в том числе для адресов loopback. HTTP передаёт ключи доступа и данные проекта
без TLS, поэтому используйте его только для намеренно выбранных локальных
или иным образом защищённых тестов.

HTTPS никогда не переходит на HTTP незаметно для пользователя.
Перенаправления отклоняются.

## Состояние и восстановление связи

### Проверьте или восстановите подключение

| Локальный инструмент | Назначение |
| --- | --- |
| `knx_connections` | Показать версии клиента и сервера, состояние, количество инструментов и ошибки настройки, транспорта или вызовов |
| `knx_refresh_connections` | Повторно подключить уже загруженные цели, при необходимости только по одному идентификатору `connection` |

Для диагностики состояние также включает идентификаторы процессов и счётчики
переданных входных данных, без путей профилей или данных доступа.
Это **последнее известное состояние**, а не непрерывный мониторинг.

Обновление подключений использует конфигурацию, уже загруженную работающим
клиентом. После изменения сохранённых настроек хоста или выбранных профилей
полностью перезапустите Claude. Обновление не ищет файлы и не перечитывает
эти настройки.

### Если инструменты появляются с задержкой

Подключения загружаются независимо. Первая выдача списка инструментов ждёт
не более одной общей секунды для уже загружаемых каталогов; инициализация
и запросы состояния остаются доступными. Каталоги, поступившие позже,
вызывают уведомления об изменении.

Если хост не перечитывает каталог, поступивший позже, полностью перезапустите
Claude после того, как конечная точка ETS будет готова.

### После потери подключения или сеанса

| Операция | Ограничение времени |
| --- | --- |
| Установление подключения | Всего 15 секунд |
| Запрос инструмента | 180 секунд |

Вызовы выполняются последовательно для каждой конечной точки, поэтому очередь
одного объекта не блокирует все остальные. После распознанной потери сеанса
запрос только для чтения может быть повторён один раз.
Изменение, ответ на которое потерян, **никогда не повторяется автоматически**.

Если получен **`PROJECT_RECHECK_REQUIRED`**, изменение не было выполнено:

1. Заново прочитайте список текущих проектов и затронутые объекты.
2. Явно укажите ключ проекта и убедитесь, что выбранная цель всё ещё верна.
3. Осознанно отправьте нужное изменение ещё раз.

Разрешения и подтверждения ETS остаются обязательными.

## Обновление и удаление

### Установите обновление

Пакеты Community обновляются вручную:

1. Установите новый пакет MCPB с тем же техническим идентификатором `knx-mcp-claude`.
2. Сохраните выбор действующих профилей v1.
3. Полностью завершите и заново запустите Claude, затем откройте новый чат.
4. Ещё раз проверьте подключение и текущие проекты.

Так же перезапускайте приложение после изменения выбранных файлов, ключей
или доверия сертификатам. Используйте инструменты, загруженные для нового чата;
не переносите имена из старой истории чата.

### Измените адрес или сертификат конечной точки

Проверьте изменение в ETS, экспортируйте профиль под **новым именем файла**
и замените старый выбор в Claude. Скрытые изменения идентичности по тому же
пути профиля отклоняются.

### Удалите расширение

Удаление расширения сохраняет файлы профилей и сертификаты.
Несекретные записи идентичности также остаются в
`%LOCALAPPDATA%/KNX-MCP/Claude/identities`. Их удаление стирает прежнюю историю
обнаружения изменений.

## Конфиденциальность

Описания, аргументы и результаты инструментов могут содержать данные проекта
или заказчика. Результаты передаются Claude и могут обрабатываться его сервисом
ИИ. Поэтому весь обмен не является исключительно локальным.

Клиент не использует промежуточный сервер издателя, не собирает телеметрию
и не отправляет данные издателю автоматически. Защищайте профили, резервные
копии и журналы и убедитесь, что имеете разрешение передавать данные проекта
сервису ИИ.

Прочитайте [политику конфиденциальности](PRIVACY.md) и
[информацию о безопасности](SECURITY.md).
