# KNX-MCP 1.2.0.4 — Release 2

**November 2026 · validated by KNX · available in the KNX Online Shop · currently free of charge**

**Official app distribution:** [KNX Online Shop (MyKNX product search)](https://my.knx.org/shop?action=search&search=KNX-MCP). This is a shop search link rather than a direct installer or product detail link.

This is a community documentation repository, **not a distribution repository for KNX-MCP binaries**. Any automatically generated GitHub “Source code” archives contain only this community repository, not an installable ETS App.

KNX-MCP 1.2.0.4 is the second public release of the ETS App. It replaces 1.1.0.0; settings and permissions are kept. The complete release notes in English and German are attached as PDF to the [GitHub release](https://github.com/knx-mcp/knx-mcp-community/releases/tag/app-v1.2.0.4).

## Highlights

- Works with **ETS5 (5.7 or later) and ETS6**.
- **Communication rebuilt, with encryption:** optional HTTPS directly in the app, the access key also as `Authorization: Bearer`, several agents at once. In many cases no proxy or bridge is needed any more.
- **New integrations:** Microsoft Scout and GitHub Copilot connect directly over MCP. Microsoft Copilot and ChatGPT reach ETS over the internet through an MCP gateway.
- **21 new tools — 97 in total:** topology, copying rooms and floors, group addresses, devices and communication objects, tunnelling addresses, KNX Secure certificates, plugin data, bus interfaces, DALI gateways and product import.
- **Much in one call:** lists instead of single calls — one confirmation, one undo step, all or nothing.
- **Consistent parameter names** across all tools; the former names are still accepted.
- **Six languages** in the panel and the help (English, German, French, Italian, Czech, Russian); the help describes every tool with all its parameters and examples.
- **Clear start:** the button reads **Start project MCP / Stop project MCP**, stays pressed in ETS6 while the project MCP runs, and the panel shows **Stopped – please start**.

## New functions

### Communication and security

- **HTTPS in the app (optional):** an own certificate on explicit request, or an existing one from the Windows certificate store; export of the public part for the client. The private key stays on the computer; the access key remains mandatory.
- **Access key as `Authorization: Bearer`:** the usual way for Microsoft Scout, GitHub Copilot and MCP gateways. The templates in the panel use it by default.
- **Gateway / reverse proxy:** additional local DNS names, trusted gateway addresses and allowed origins, each released exactly.
- **Several agents at once:** connected clients with name, bridge, address and running tool (`server_get_clients`); every undo step names the client.
- **Resume after an ETS restart** (optional, off by default) for clients that do not reconnect by themselves.
- **Templates in the panel** for HTTPS, Claude one-click installation, Claude Desktop, Claude Code and Microsoft Scout; export of a connection profile for the Claude extension.
- **Connection diagnostics in the panel:** one compact line per event, full export for support.

## Changed and extended functions

- **Devices and parameters:** `device_set_parameter` writes many parameters, also across devices (up to 500), in one step, resets to the default, accepts durations as in the ETS dialog and is much faster in large projects; `allow_hidden` for hidden parameters of devices with an ETS legacy plugin. `device_get_parameters` filters by channel, dialog page and internal name and explains why a parameter cannot be changed. `device_get_channels` filters linked and unlinked objects, pages, and has a short form. `device_link_object` makes many links in one call and sets the sending address. `device_create` and `device_copy` check ETS nesting rules first, take products from the online catalog without the import wizard, and set address and name per copy. `device_get_list` shows order number and manufacturer.
- **Group addresses:** `ga_create` with several addresses, each with its own datapoint type; `ga_update` for many names and datapoint types at once; `ga_delete` with lists and trial run, now also in ETS6; `ga_find` and `ga_explain` show the direction and hint at a missing bus interface link or an address that nothing in the project receives; `ga_read_value` names the objects that take a response as their new value, and with `check_address` checks first.
- **Building, topology, project, bus:** building parts with “/” in their name; room usage independent of the ETS language; `project_validate` with hints to bus interfaces; `bus_health` detects a lost bus connection; compatibility mode shown in `project_get_info`, `ets_list_projects` and the About window; `telegram_get_recent` with `wait_seconds` waits up to 120 s for a matching telegram.
- **Consistent parameter names:** a device is `device`, an individual address as a value `individual_address`, a group address `address`; the target when creating `parent`, when copying `into`, when moving `to`.
- **Panel and help:** six languages, following the ETS language; help (CHM) through the “?” button in ETS; the confirmation shows what a call concerns, with “Allow for this session”.

## Fixed issues

- MDT module devices in ETS5 (e.g. heating actuators): channels, objects, links and parameters are complete.
- Very large applications (e.g. DALI gateways): no call hangs for minutes any more.
- “Unknown error” replaced: every error message names the actual cause, with new codes such as `PARENT_TYPE_NOT_ALLOWED`, `ETS_BUSY`, `PLUGIN_OPEN` and `ALREADY_RUNNING`.
- The same changing call is no longer carried out twice when a client repeats it after its own timeout.
- Names with special characters are written and read back unchanged.
- `bus_scan_line` in ETS5 scans ranges and single addresses correctly.
- Some clients do not pass on an argument named `device` — `device_address` is accepted everywhere as an equal name.
- `device_set_parameter` writes choice parameters by their key and reads them back.

## Compatibility

- Existing client configurations with the header `X-KnxMcp-Key` keep working.
- The former parameter names are still accepted; the tool list names only the new ones.
- New arguments are optional — without them every tool answers as before.
- Also runs in ETS compatibility mode (32-bit) in ETS5 and ETS6.
- Settings and permissions from 1.1.0.0 are kept.
- After the update, restart the AI client or start a new chat so it loads the new tool list.

## Notes

- Every change is one ETS undo step. ETS does not take back download flags, datapoint types of objects, device certificates and the product import into the catalog — the answers point this out each time.
- Tools that act on the installation (programming, unloading, restart, line scan) are blocked by default.
- By default the endpoint can be reached only from the own computer; project data leaves the computer only through the connected AI client.

The complete product documentation and release material distributed with the app remain authoritative for the released package.
